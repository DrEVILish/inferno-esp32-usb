# 13 — Cross-module review (A1), 2026-10-13

Scope: all of `firmware/main` after the merge of the three modules (usb/,
net/+clock/, aoip/), read at the seams: ring contracts, ISR/IRAM safety,
cores and priorities, init order, epoch handling, error paths, atomics. The
AoIP control plane (ARC, CMC, flow control, subscriber, mDNS, info) was
reviewed by a second reader in parallel. Nothing here has run on hardware.

Line numbers refer to branch `feat/harden` after the fixes.

## 2. Checked, no change needed

- **Ring contracts.** Indices are media frames everywhere (RX: packet
  `sec·48000+sub` + shift; TX: packet timestamp = ring index of its first
  frame; USB: SOF media frame ± lead/latency). Samples are left-justified
  int32 on both sides (RX decode `<<8`/`<<16`, 32-bit input masked to 24;
  TX takes the top bytes). `net_to_usb` is read-and-cleared by USB IN only in
  production; the NET_LOOPBACK and USB_LOOPBACK builds never clear it (TX
  resp. nobody reads it). `ring_valid()` window `head − frame ≤ 960` holds
  with lead ≤ 48 + fpp ≤ 32 + lag ≤ 48.
- **RX late check vs IN read.** IN reads frames `< sof_f − L − m` (m = IN
  margin), `sof_f` on the lower envelope of SOF times, so never later than
  the read itself; the RX hook drops a packet if its first ring frame is
  `< now − L`. Any accepted frame is therefore unread, and a read frame is
  never written later, provided the hook writes within m frames (+ ISR
  latency) of reading `now` (it runs at the highest task priority, µs). With
  m = 3 frames (62 µs, was 6) — docs/14-latency.md.
- **64-bit atomics on rv32 (`audio_ring_t.head`).** Not lock-free: GCC emits
  `__atomic_load_8/__atomic_store_8`, which IDF's `esp_libc/stdatomic.c`
  implements with one global `portENTER_CRITICAL_SAFE` spinlock. That is
  correct across cores and in ISRs (SAFE variant), and the code is in IRAM
  (`CONFIG_LIBC_MISC_IN_IRAM=y`; `check_iram.py` walks into it). Cost: one
  short global spinlock per ring head access (USB ISR write, packetizer
  `ring_valid`). Acceptable; a seqlock or 32-bit head would remove it if
  profiling ever shows contention.
- **Cache maintenance for DMA.** TinyUSB cleans IN buffers before arming
  (`dcd_edpt_xfer`) and invalidates OUT buffers before the completion
  callback; our buffers are 64-byte aligned, whole lines, and the CPU never
  writes the OUT buffers (no dirty lines to evict over DMA data). The 4-byte
  feedback buffer is a full line.
- **Init order** (`app_main.c`): NVS → rings → `net_start` (esp_netif/lwIP
  init, EMAC, 1588 enable) → `mc_start` (counter init, PTP task/hook/join)
  → `uac2_start` (SOF ISR uses an initialised counter) → `aoip_start`
  (sockets after lwIP; binds to INADDR_ANY work before an address) →
  telemetry. Before link/IP: joins fail with INVALID_STATE and the
  `net_maint` task re-joins on link-up; TX destinations stay unresolved and
  are retried by `ftx_tick`.
- **Multicast contract.** RX bundles join via `net_mcast_join()` (239/8 fast
  path filter), PTP joins 224.0.1.129 the same way.
- **Test variant routing.** USB_LOOPBACK: IN reads `usb_to_net` at
  `now − 192` (non-clearing); NET_LOOPBACK: TX reads `net_to_usb` at
  `ts − L` without clearing, USB IN sends silence and never clears; TONE:
  TX ignores rings.
- **Stacks.** EMAC RX 6 KB (hooks use < 300 B), packetizer 4 KB (packet
  buffer static), USB task 4 KB (control requests only), ctl 8 KB, sub
  6 KB (after fix 11), telemetry 4 KB (8 KB buffer is static).
- **Integer wrap.** 64-bit frame indices everywhere on the audio path;
  32-bit ms timestamps compared by subtraction.

## 3. IRAM check (A2) — what it covers

`tools/check_iram.py <elf>` (run by `tools/build.sh` and
`tools/build-variant.sh` / `build-matrix.sh` after every build):

- Roots: `dwc2_int_handler_wrap` (TinyUSB DWC2 ISR), `uac2_sof_isr`,
  `uac2_xfer_isr` (called through the class driver table), the AoIP TX
  `timer_cb` (esp_timer ISR dispatch).
- Edges: direct calls/jumps, plus loaded function addresses (treated as
  possible indirect calls). Result today: 70 functions reachable, all in
  IRAM or ROM.
- Data: references to `.flash.rodata`/PSRAM fail the check for our code and
  TinyUSB (e.g. it caught `_dwc2_controller`, a const table in flash, before
  the linker fragment moved it). IDF's own IRAM functions reference flash
  only for assert strings; those are reported with `-v`, not failed.
- Justified exceptions (`ALLOW` in the script): FIFO mutex paths in
  `tusb_fifo.c` (no FIFO has a mutex: our driver uses plain buffers),
  `dcd_event_handler → xQueueGenericSend` (task branch; in the ISR it is the
  FromISR call), `prvCopyDataToQueue → xTaskPriorityDisinherit` (mutexes
  only).
- Not covered statically: the data the ISR touches through pointers set at
  run time (`g_ring_*.buf` from `heap_caps_aligned_calloc(INTERNAL|DMA)`,
  DMA buffers in `.bss`) — internal RAM by construction.
- `uac2_start()` logs an error if the `esp_intr_alloc` wrap did not run.

## 4. Not fixed (with reason)

| where | issue | why not now |
|---|---|---|
| `net/net.c` hooks | Re-registering a hook slot while the RX task is inside the old hook can call the new `fn` with the old range for one frame. | `net_udp_hook_unregister()` is never called; all hooks are registered once at start. |
| `aoip/aoip_mdns.c` A-record fallback | `mdns_query_a()` (3 s) runs per channel, serially; 32 subscriptions to one badly-announcing host can block the subscriber ~100 s. | Control-plane latency only; cache per hostname when it is seen on the bench. |
| `aoip/*` under `aoip_lock` | `frx_add_flow` quiesce (2 ms) and socket work, `publish()` waiting for the packetizer ack, NVS flush, `mdns_hostname_set` run under the recursive lock. | Stalls the ctl/sub tasks only (no lock-order cycle: tcpip, mdns, packetizer and the EMAC hook never take it). |
| `aoip/subscriber.c` | `fpp = max(fpp_min, …)` can exceed the latency cap / MTU when a transmitter's minimum is large. | The transmitter would refuse or we count `rx_late`; Dante/Inferno minimum is 2–16. |
| `aoip/flowctl_client.c` | OK reply shorter than 6 bytes: error returned, transmitter keeps the flow until keepalive timeout. | Harmless. |
| NVS blobs | Their size depends on `UI_CHANNELS`; flashing a different channel build drops names/subscriptions (length check → defaults). | Test builds only; production is one channel count. |
| Flash writes vs network | The network side (EMAC RX task, packetizer, lwIP) is flash-resident and pauses during an NVS write; USB keeps running (A2). | Moving the whole network fast path to IRAM is large; A3 makes writes rare and controller-initiated. Option for later: `CONFIG_SPI_FLASH_AUTO_SUSPEND` (P4 supports it; flash-part dependent). |
| USB OUT lead vs ISR stalls | No lead ≤ 1 ms absorbs a 1 ms USB ISR blackout without an OUT re-anchor (simulated). | Post-A2 there is no known source of ms stalls; docs/14 states the assumption. |
| `tools/aoip_probe.py` `paged()` | Pages 0x2200/0x3200 by count instead of slot index; sparse tables page wrongly. | Bench tool; fix when used against sparse tables. |
