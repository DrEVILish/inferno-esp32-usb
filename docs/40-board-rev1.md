# 40 — Own board, rev 1 (USB-C + RJ45, ESP32-P4 chip-down)

Status: **schematic complete as code, ERC clean, board outline/stackup/placement of the
key parts done, not routed.** Everything in `hardware/` is generated by
`hardware/build.sh`; see `hardware/README.md` for the tool flow.

The box does exactly two things: AoIP (Inferno-compatible, 10/100 RMII with the EMAC's
IEEE 1588 timestamps) on an RJ45, and USB Audio Class 2.0 (32×32, HS) on a USB-C port.
It is bus powered, has no buttons and no configuration, and boots on power. The
firmware is the one that runs today on the Waveshare ESP32-P4-ETH. Rev 1 keeps all of
its Ethernet pins (§5) and needs only the deltas in §15.

Facts are tagged with their source. A fact this pass could not check is marked
**UNVERIFIED**.

### 3.2 Power tree

```
VBUS_C (USB-C, 4.40–5.25 V; 1 µF + 0.1 µF, TVS)            [< 10 µF ahead of the switch]
 └─ TPS25200 (ILIM 150 k → 590–710 mA, soft start ~2–3 ms, 5.4 V clamp, 7.6 V OVLO, EN = VBUS/2)
     └─ VBUS_5V (10 µF + 4.7 µF)
         └─ TLV62569 #1, 100 k / 22 k → 3.33 V, 2× 22 µF                       +3V3 (≤ 2 A)
             ├─ P4 3V3 domains (LP, IO_0/4/5/6, ANA, BAT, LDO, DCDCC, USBPHY)
             ├─ TLV62569 #2 (EN = P4 EN_DCDC, FB = P4 FB_DCDC + 499 k/499 k/22 p) → VDD_HP ≈ 1.1 V, 22 µF + 10 µF
             ├─ W25Q128 via P4 VDDO_FLASH (3.3 V)
             ├─ PHY_3V3 (0R) → IP101GRI VDDIO + AVDD33, 50 MHz XO (0R, ferrite option), magjack yellow LED
             └─ status LED
```

Rationale for the VDD_HP buck: [HDG 1.3.2] requires it and also requires that "the
input of the external DCDC is the same as the VDD_DCDCC power supply". That is +3V3,
not VBUS. EN_DCDC is 0 V in download mode and before firmware runs [HDG], so the core
supply comes up under ROM control.

| ESP32-P4 at 400 MHz, both cores busy, all peripheral clocks on, incl. VDD_HP buck input | 150 mA | — | [DS Table 5-7] "Typ2" 150 mA (3.3 V supply, 25 °C) |
| + PSRAM/flash traffic, USB HS PHY (≤ 20 mA [HDG]), EMAC | +60 mA | — | estimate (UNVERIFIED); the PHY and flash figures are maxima |
| P4 incl. flash and PSRAM, design figure | — | **380 mA** | [HDG 1.3.2]: "minimum operating supply current 380 mA (including flash and PSRAM)" |

| **3V3 total** | **≈ 265 mA** | **≈ 445 mA** | |
| **VBUS input** (buck η ≈ 0.90 typ / 0.85 worst) | 265·3.3/(5.0·0.90) ≈ **195 mA** | 445·3.3/(4.40·0.85) ≈ **393 mA** | |

The board stays under 500 mA even at the 380 mA Espressif design figure and the
minimum USB voltage. That leaves about 100 mA of margin. The eFuse limit (590 mA
minimum) sits above the worst case and below what a USB 2.0 port must supply.
**USB descriptor: `bMaxPower` = 400 mA** (the field is in 2 mA units, so the value
is 200). That covers the 393 mA worst case and stays below the 500 mA high-power limit
(firmware item, §15).

**Known deviation: unconfigured current.** USB 2.0 §7.2.1 allows a device only one unit
load (100 mA) until the host sends SET_CONFIGURATION. This box draws about 195 mA from
VBUS as soon as it is attached: the P4 runs at full clock and the PHY and 50 MHz XO run
at once. Hosts and hubs tolerate this in practice, but it is not compliant. Bench-test
the figure (UNVERIFIED on hardware). **Mitigation (firmware, no hardware change):**
until SET_CONFIGURATION, keep GPIO51 low so the PHY stays in reset (the 10 k
pull-down already holds it there from power-up, saving ≈45 mA), run the CPU at a low
clock (e.g. 40–100 MHz; [DS Table 5-7] gives 40–63 mA at 100 MHz against 150 mA at
400 MHz), and keep the AoIP stack idle. Then raise to 400 MHz and release the PHY in
the set-config callback. This should bring the attach current to roughly 80–100 mA
(estimate, UNVERIFIED). The cost is that Ethernet only starts once a USB host has
configured the device. That is acceptable, because the box is useless without USB.
The XO cannot be gated (no enable line is wired); its ≤ 10 mA is part of that figure.

## 4. Strapping configuration

[DS §3, Table 3-1/3-3/3-7], [HDG 1.3.8]

| strap | default | rev 1 | effect |
|---|---|---|---|
| GPIO35 (also RMII TXD1) | weak pull-up = 1 | **10 k pull-up**, BOOT pin on the Tag-Connect | 1 = SPI boot. Pulling BOOT low during reset gives Joint Download (USB-Serial-JTAG, UART0, …). No capacitor on GPIO35 [HDG]. IP101 TXD1 is a Hi-Z input with no internal pull [IP pin table], so the PHY cannot pull the strap low. The 22 R series resistor sits on the PHY side, and the PHY is held in reset (Hi-Z) by its 10 k pull-down |

| GPIO37/38 (UART0) | floating | UART0 TX/RX to the Tag-Connect | "any value" in Table 3-3 |
| GPIO34 (also RMII TXD0) | floating, no internal pull | no pull (same as [WS]/[EVX]) | JTAG source select is used **only** if EFUSE_JTAG_SEL_ENABLE = 1. Default eFuses ignore it [DS Table 3-7]. Never burn that eFuse on this board |
| VDDO_FLASH voltage | eFuse 0 → 3.3 V | not burned | 3.3 V flash |

IP101GRI latched pins, 5.1 kΩ each per [IP Table 12], as in [WS]:
COL/RMII = 1 (RMII), CRS/LEDMOD = 1 (LED mode 2: LED0 = link/act, LED3 = 100M link),
PHY_AD0 = 1 and PHY_AD3 = 0 (**PHY address 1**, as the firmware expects),
RXDV/CRS_DV/FX_HEN = 0 by internal pull-down (twisted pair, not fiber).
TXER is pulled down because "TXER must be floating or GND in RMII mode" [IP pin 1].
The magjack LED polarity follows the straps: the yellow LED goes from PHY_3V3 to LED0,
the green LED from LED3 to GND.

## 6. USB

- **HS OTG (UAC2):** the dedicated pads USB_DP (50) and USB_DM (49) [DS Table 2-10].
  The path is USB-C A6/B6 and A7/B7 (both orientations joined at the receptacle) →
  TPD2EUSB30 at the connector → 0R pair placed at the P4 ("reserve space for
  resistors/capacitors close to the chip" [HDG 1.4.3]) → pads. 90 Ω ±10 %
  differential, on top layer over solid GND, minimal vias with return vias at each
  transition [HDG 1.4.3]. A 1 MΩ DP pull-down is footprinted DNP; it was mandatory on
  v1.x and is optional on v3.x [HDG 1.3.12]. There is no REXT or other external part
  for the HS PHY.
- **CC:** 5.1 kΩ Rd on CC1 and CC2 makes the port a UFP sink, so the source supplies
  vSafe5V only. No PD. SBU is NC.
- **VBUS:** TVS → TPS25200. Capacitance ahead of the switch is 1.1 µF, well under the
  10 µF USB 2.0 limit. The eFuse soft start (t_r ≈ 2–3 ms typ [TPS 5.6]) charges about
  15 µF downstream at 15 µF·5 V/2 ms ≈ 40 mA, and the 3V3 buck has its own soft start.
  EN = VBUS/2 (100 k/100 k). Note that the EN abs max is 7 V. A VBUS above 14 V would
  over-stress EN even though IN tolerates 20 V. A UFP without PD only ever receives
  5 V, so rev 1 accepts this (risk R7).
- **USB-Serial-JTAG (FS):** GPIO24 (D−) / GPIO25 (D+) are the default USJ pads [HDG
  1.3.12]. They go only to test pads for production flashing and debug, so the single
  USB-C always carries the UAC2 device. Joint Download (BOOT low) also supports
  "USB 2.0 OTG download at Full-Speed" over the HS port [DS Table 3-3 note]. That makes
  first-time flashing through the USB-C itself possible (UNVERIFIED on v3.x; test on the
  first board).

## 7. Clocks

### 7.1 40 MHz system crystal
40 MHz is the only frequency the firmware supports. Tolerance is ±10 ppm [HDG
1.3.5]. X322540MPB4SI has CL = 15 pF; C = 2·(15 − ~4 pF stray) ≈ 22 pF, to be tuned on
the first build as [HDG] says. A 0R in series on XTAL_P and XTAL_N sits next to the
chip, as R3/R4 in [HDG Fig. 1]. The crystal sits ≥ 4.5 mm from the XTAL pins, with no
vias on the clock traces and nothing routed under it [HDG 1.4.2] (also a DRC rule).

### 7.2 50 MHz RMII reference (decision record)
The requirement is "a 50 MHz oscillator feeding P4 REF_CLK (GPIO50) and the PHY,
exactly as the Waveshare ESP32-P4-ETH". **The Waveshare schematic shows something
different.** [WS] page 1 has a **25 MHz** 4-pin crystal (Y3, 20 pF caps) on IP101 X1/X2.
The PHY's RXCLK/50M_CLKO (pin 14) drives GPIO50 and its own 50M_CLKI (pin 10).
Espressif's [EVX] does the same (25 MHz ±10 ppm crystal, 0R on RMII_CLK). docs/11 §1
("50 MHz from the board oscillator") should be corrected to "from the PHY".

Rev 1 still uses a **separate 50 MHz XO**, as required. This is a valid IP101
configuration: "Clock 50MHz provides a clock source 50MHz into pin TXCLK/50M_CLKI and
connect pin X1 to GND" [IP Table 3, pin 2]. It has three advantages:
1. REF_CLK runs regardless of PHY state. With the PHY-sourced clock, every PHY reset
   (GPIO51) also stops the EMAC's RX/TX clock. The EMAC DMA soft reset needs that clock
   (a frequently reported "EMAC reset timeout" in ESP-IDF; UNVERIFIED for IDF v6.1).
2. One clock domain with a defined source (±25 ppm XO). The PHY PLL is not part of
   the media-clock path that the 1588 servo disciplines.
3. Firmware is unchanged: `EMAC_CLK_EXT_IN` on GPIO50 either way.

**Fallback by population (DNP option B = the [WS]/[EVX] scheme).** Both schemes are on
the board, and the parts fitted decide which one is active. Firmware is identical
(GPIO50 is a REF_CLK input in both):

| part | option A (default): 50 MHz XO | option B: IP101 25 MHz crystal, PHY drives REF_CLK |
|---|---|---|
| X1 50 MHz XO (+ its 0R/decaps) | fitted | **remove** (or remove its supply 0R) |
| 0R PHY_X1 → GND | fitted (X1 must be GND in 50 MHz-input mode [IP pin 2]) | **remove** |
| Y2 25 MHz crystal on X1/X2 + 2× 20 pF | DNP | **fit** ([WS] Y3, C113/C120 20 pF) |
| 22R PHY_50M_CLKO → OSC50_OUT star | DNP | **fit** |
| 22R star → GPIO50, 22R star → PHY 50M_CLKI | fitted | fitted (unchanged) |

In option B, 50M_CLKO feeds both the MAC and the PHY's own 50M_CLKI through the same
star, as [WS] ties pins 10 and 14 together. The star node is laid out once and serves
either source, so the layout must keep the CLKO stub from pin 14 short. Remember that
in option B, REF_CLK stops whenever the PHY is in reset (risk R5).

The layout must follow the [IP §6.1] note: "the clock trace length to IP101G must equal
the clock trace length to MAC", and jitter < 500 ps p-p. That means a star from the XO
with one 22R per branch at the source, both branches equal (DRC rule: 4–14 mm, ≤ 1
via), and a guard / GND stitch on both sides. RESET_N timing (≥ 10 ms reset, clock
valid ≥ 10 ms before release [IP Table 14]) is met because the PHY is held in reset by
a 10 k pull-down until firmware releases GPIO51. The firmware's pulse is long enough
only if it is ≥ 10 ms (§15).

## 8. Ethernet

- RMII per §5. 22R series at the driver end of all six data lines (TXD0/1, TX_EN at the
  P4; RXD0/1, CRS_DV at the PHY) and on both clock branches [HDG 1.3.14]. RMII timing:
  T_su 4 ns, T_h 2 ns, Td ≤ 12 ns [IP Tables 17/18]. At 50 MHz this is comfortable
  for traces of a few cm; the DRC caps them at 40 mm.
- MDIO 1.5 k pull-up (as [WS] R59); MDC ≤ 2.5 MHz [IP].
- ISET 6.19 kΩ 1 % [IP pin 25] (WS uses 6.2 k). REGOUT 10 µF + 0.1 µF [IP pin 28];
  REGOUT must not feed anything else [IP Table 1 note].
- Magjack centre taps: **decoupling capacitors only, never a supply**. IP101G is a
  voltage-mode driver with built-in 49.9 Ω terminations ("Center-tap of transformer:
  Do not connect to any power" [IP Table 1]; "connected to decoupling capacitors
  respectively" [IP §6.2]). Rev 1 uses 100 nF on TCT and on RCT separately. [WS] ties
  both to one 22 nF.
- Bob-Smith node (HR911105A pin 8) and shield go to CHASSIS. CHASSIS connects to GND
  through 1 MΩ ∥ 10 nF/100 V, plus a DNP 0R for a hard tie if EMC testing prefers it.
  [IP §6.1]: "Place a gap between the system and chassis grounds."
- MDI pairs: 100 Ω differential, as short as possible, with 3× spacing to other nets
  [IP §6.2]. No GND or power plane under the magjack's line side. Only CHASSIS copper
  between the magjack and the board edge.
- HR911105A LED pin polarity is taken from the KiCad symbol (yellow 12 = A / 11 = K,
  green 9 = A / 10 = K). **UNVERIFIED** against the HanRun drawing, because the LCSC

## 10. Layout rules (for the routing pass)

`hardware/kicad/usb-inferno.kicad_dru` encodes the checkable ones.

1. **L2 is unbroken GND** under the whole board except the CHASSIS strip at the
   connector edge. No slots under USB, RMII, the crystal or the XO.
2. **HS USB:** top layer only, pair skew ≤ 0.15 mm, uncoupled length ≤ 2 mm,
   ≤ 2 vias (DRC), with ground return vias next to any via. ESD at the connector, then
   the 0R pair at the chip. Keep the pair away from the SW nodes and the 50/40 MHz
   clocks by ≥ 3w.
3. **RMII:** all lines ≤ 40 mm (DRC); REF_CLK branches equal ± a few mm (DRC window
   4–14 mm); series R at the driver; GND stitching along REF_CLK.
4. **MDI:** 100 Ω pairs, skew ≤ 0.3 mm, PHY close to the magjack.
5. **Crystal:** [HDG 1.4.2]: ≥ 4.5 mm from the chip clock pins, no vias on XTAL
   traces (DRC), caps at the crystal end, GND copper and via fence around it, nothing
   under it, no inductors nearby (L1/L2 are ≥ 10 mm away in the placement).
6. **Decoupling:** 0.1 µF per supply pin, at the pin, through its own via to L2
   [HDG 1.4.1]. Star-feed the P4 rails. 10 µF at VDD_LDO and VDD_DCDCC.
7. **VDD_HP buck** next to the P4 EN_DCDC/FB_DCDC corner. Short input, output and FB
   loops [HDG 1.4.1]. FB sense from the P4 VDD_HP plane side, not the inductor pad.
8. **Thermal pad:** the QFN104 EP has 3×3 Ø0.25 mm vias between the 4×4 paste
   windows (~56 % paste). Order with via-in-pad **resin filled and capped**, or tent
   the vias from the bottom. IP101 uses KiCad's QFN-32 ThermalVias footprint.
9. **Edge:** USB-C and RJ45 overhang the left (short) edge by 0.6 mm (courtyard
   front). Copper keeps ≥ 0.3 mm from the edge.
10. **Fine pitch:** QFN104 has 0.35 mm pitch, 0.20 mm pads and a 0.15 mm gap.
    Net-class clearances are 0.15 mm so escape works. Check JLC's assembly capability
    for 0.35 mm QFN (UNVERIFIED) and use a 0.1 mm stencil.

## 12. ESD / EMI

- USB D±: TPD2EUSB30 (IEC 61000-4-2 level 4 contact [TPD]) at the receptacle, ≤ 1 pF.
- VBUS: SMAJ5.0A + eFuse OVLO; CC lines rely on the receptacle and the 5.1 k Rd (an
  ESD diode option is not footprinted; consider it for rev 2).
- Ethernet: the magjack's isolation (1500 Vrms class, UNVERIFIED for HR911105A), Bob-Smith

- Clocks: series R at the source, short and guarded traces, XO supply via 0R (fit a

## 13. Programming and debug

TC2030-IDC-NL footprint (no legs, no BOM part). Pins: 1 3V3 · 2 EN (CHIP_PU) · 3 GND ·
4 U0TXD (GPIO37) · 5 U0RXD (GPIO38) · 6 BOOT (GPIO35). The host adapter must not

## 14. PoE (not on rev 1)

Rev 2 option: isolated 802.3af PD (e.g. a TPS2378/Si3404-class PD controller with an
active-clamp or flyback to 5 V, ~22 × 16 mm including the 1.5 kV creepage gap).
Its 5 V would be OR-ed with VBUS_5V through an ideal-diode pair (LM66100-class, or
AO3401A + LMBT3906DW discrete as [EVX] page 6 "Ideal Diodes") **after** the eFuse.
This needs a **PoE-rated magjack** with centre taps brought out (HR911105A is not one),
so the RJ45 footprint changes in rev 2. On rev 1 the bottom-right area of the board is
free of parts and is marked on Cmts.User.

## 15. Firmware deltas for this board (all constants, no code)

- `UI_PIN_STATUS_LED 20` (new; active high).
- Build for **chip rev v3.x** (`CONFIG_ESP32P4_SELECTS_REV_LESS_V3=n`, the default in
  IDF ≥ 5.5.3/6.0 [REV3 2.1.2]). [WS] has pin 54 = NC, i.e. **v1.x silicon**, so
  bench boards and this board need **different binaries** [REV3]. `CPU_FREQ_400`

## 16. Tooling and ERC

SKiDL 2.3.0 works with KiCad 9's symbol libraries, so no alternative was needed. Its
output is a **netlist**, not a `.kicad_sch`. ERC is therefore SKiDL's pin-type ERC
(power-in driven, outputs not shorted, unconnected pins explicitly NC):
**0 errors, 0 warnings** (`hardware/erc.log`). Rails carry `drive = POWER`, which is
the PWR_FLAG equivalent. KiCad's own schematic ERC cannot run without a schematic
sheet. If the team wants a drawn schematic for review, it has to be drawn from the
netlist in Eeschema (SKiDL's schematic generator only supports KiCad 5/6). The PCB is
built with the pcbnew Python API from the netlist (pads ↔ nets) and checked with
`kicad-cli pcb drc`. The only remaining violations are the expected ones for an
unrouted board: unconnected items, silk overlaps of staged parts, and REF_CLK length
(no tracks yet).

## 18. What remains for the human layout pass

1. Move the staged passives (right of the outline, grouped by IC) next to their pins
   (decoupling first), following §10.
2. Route, in this order: VDD_HP buck → P4 power → HS USB pair → RMII + REF_CLK star
   → MDI → crystal → flash QSPI → the rest. Then add VDD_HP / VBUS_5V islands to the L3
   pour and stitch GND.
3. Fill the zones, run DRC (it must then be clean apart from Cmts), and set JLC
   controlled impedance with the §9 stackup.
4. Add silkscreen: polarity, the USB/ETH legends, the Tag-Connect outline and the
   board name.
5. Generate fabrication outputs (Gerbers, drill, CPL) and a JLC-format BOM from
   `hardware/bom.csv`.
